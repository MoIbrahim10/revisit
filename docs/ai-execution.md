# Live AI execution

Live mode is optional. Configure the following variables in both the web and worker process environments; no model is selected by default. The adapter makes no credential checks or inference calls during setup. Recorded mode remains independently usable.

| `AI_PROVIDER` | Credential variable | Chat Completions base URL |
| --- | --- | --- |
| `openrouter` | `OPENROUTER_API_KEY` | `https://openrouter.ai/api/v1` |
| `nvidia` | `NVIDIA_API_KEY` | `https://integrate.api.nvidia.com/v1` |
| `openai` | `OPENAI_API_KEY` | `https://api.openai.com/v1` |

Set `AI_MODEL` to a model ID available to the selected account that supports strict `response_format: json_schema` and reports model identity and token usage. Restart both processes after changing their environment. Existing `OPENAI_API_KEY` + `OPENAI_MODEL` configuration remains supported when `AI_PROVIDER` is absent; `AI_MODEL` takes precedence. A key for another provider never substitutes for the selected provider's key.

For OpenRouter only, optional `AI_REASONING_EFFORT=none|low|medium|high` sends an explicit reasoning effort; leaving it unset preserves the provider's default. Other providers reject this setting. Check the chosen model's supported efforts: some require reasoning and cannot accept `none`. Reasoning can consume the same output-token budget as the final JSON, leaving a truncated or empty answer; hiding reasoning with `exclude` does not prevent that consumption. The measured Nex mini default exhausted an assessment's bounded output before returning JSON, so an explicit supported lower effort or `none` is appropriate to evaluate for this extraction/wording workload. Request caps, timeouts, validation, and retry budgets remain unchanged. [OpenRouter reasoning controls](https://github.com/openrouterteam/docs/blob/main/guides/best-practices/reasoning-tokens.mdx)

For free testing, OpenRouter's public catalog listed `nvidia/nemotron-3-super-120b-a12b:free` with structured-output support when checked on September 17, 2026. This is a configuration candidate, not an inference-quality evaluation or a guaranteed available endpoint. Check the current [model catalog](https://openrouter.ai/models) and [rate limits](https://openrouter.ai/docs/api_reference/limits). OpenRouter requests include `provider.require_parameters: true` so routing must support the requested schema; the application never adds fallback models. OpenRouter can route among endpoints serving the configured model independently of application retries.

NVIDIA's [Developer Program](https://docs.api.nvidia.com/nim/docs/product) provides hosted endpoints for free prototyping. Select the exact ID from the [API catalog](https://build.nvidia.com/) and check that model's request parameters: Chat Completions compatibility does not guarantee JSON-schema support. Unsupported schema requests fail visibly; the application does not silently replace them with unconstrained text. Neither provider's free access implies production availability or an SLA.

The adapter uses Vercel AI SDK's `generateText` with `Output.object` and its OpenAI-compatible Chat Completions provider. There is no direct OpenAI SDK dependency. Live extraction first builds a high-precision claim set for the bounded metric vocabulary directly from source passages. Model extraction is accepted only when it validates and covers the same high-confidence evidence; otherwise the grounded set is used. The server owns IDs, offsets, values, dates, findings, criteria, and the headline. Assessment generation is limited to optional cited wording. With no extracted claims, the deterministic insufficient-evidence assessment is retained without a model call.

Question context is restricted to the supplied sources from the immutable snapshot. Retrieval must include both sides of relevant conflicts. A deterministic renderer can answer the supported customer, revenue, retention, team, change, and founder-question intents from validated snapshot structures. Model prose is accepted only when citations, conflict coverage, requested metric coverage, dates, and numbers validate; otherwise the renderer supplies the answer and explicit unknowns.

This conservative numeric rule also excludes restating a numeric thesis threshold that is not itself an extracted source claim. The model can describe whether the criterion is unresolved and cite its underlying counts; the deterministic criterion panel remains the authority for the threshold. Numeric checks are not a general semantic entailment test.

Assessment wording receives the claims and structural finding/criterion references and statuses, rather than prior narrative summaries or founder questions that could contain computed gaps or uncitable thresholds. Generated text must keep claim IDs in the dedicated citation array and copy dates as complete ASCII ISO dates. The numeric validators are unchanged by this prompt boundary.

All source material is serialized as untrusted JSON with escaped delimiters. The model receives no tools. Requests use a 120,000-character input ceiling, bounded output tokens (8,000 extraction; 2,000 assessment or answer), and a 45-second timeout. OpenAI uses `max_completion_tokens` and `store: false`; NVIDIA and OpenRouter use `max_tokens`. Provider retention policies still apply; `store: false` is not a cross-provider privacy guarantee. SDK retries are disabled so the durable workflow owns its two-attempt retry budget. Refusals, incomplete responses, malformed outputs, missing metadata, unavailable providers, and failed evidence validation cannot publish model content. The stage instead emits `hybrid-fallback:<code>`, omits an accepted token count, and publishes a validated grounded output. Raw provider payloads are never exposed.

Successful calls return the provider-reported model ID and actual total token count. Fallbacks retain their reason in the same model field, so model assistance and deterministic recovery remain distinguishable in Activity. Offline tests inject the SDK transport and exercise all three provider URLs, strict schemas, fabricated citations and quotes, numeric mismatches, conflict omission, unavailable providers, injection-shaped text, and grounded recovery. Structured validation proves source fidelity and limited consistency; it does not prove that a quoted business claim is true. An analyst retains the decision.

Implementation references: [Vercel AI SDK structured output](https://github.com/vercel/ai/blob/main/content/docs/03-ai-sdk-core/10-generating-structured-data.mdx), [compatible provider](https://github.com/vercel/ai/blob/main/content/providers/04-openai-compatible-providers/index.mdx), [OpenRouter structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), and [NVIDIA API quickstart](https://docs.api.nvidia.com/nim/docs/api-quickstart). The adapter does not rely on model-specific sampling parameters or an assumed model entitlement.

## Bounded live verification

`scripts/verify-live.ts` exercises the real adapter with fictional evidence. Supply `OPENROUTER_API_KEY` in the process environment through your own credential management, then run:

```sh
AI_PROVIDER=openrouter AI_MODEL=nex-agi/nex-n2.5-mini:free AI_REASONING_EFFORT=none npx tsx scripts/verify-live.ts
```

The script does not load a key file or `.env` file. Missing configuration exits with code 2 before any request. Before inference, it verifies the explicit `:free` model against OpenRouter's public catalog: text output, structured-output support, and zero prompt, completion, and request prices are required. The random free router is deliberately excluded so the selected model is identifiable. No automatic model fallback is supplied.

The normal path makes 11 model requests, with a hard ceiling of 12, no SDK retries, and the adapter's existing 45-second request timeout. A quota, rate-limit, or access failure is recorded and the adapter continues with grounded output; the harness stops further requests only if such a failure escapes that boundary. The cases cover the original six source metrics and customer conflict, an unsupported cash/runway question, changed fictional values, an embedded instruction to fabricate a count, and evidence containing no numeric metrics. Each case uses its actual extracted claims; failed prerequisites cause dependent checks to be skipped, never replaced with recorded results. The adapter's production validation remains unchanged.

Results are written after each step to `.local/live-verification.json`. The report contains fictional inputs, validated results, model text for inspecting rejected outputs, sanitized errors, latency, HTTP status, provider-reported model identity and usage where available, and pass/fail/skip counts. Missing usage remains unknown rather than being represented as zero; `totalReportedTokens` sums only known usage. The credential is excluded and defensively redacted from serialized output. This command does not write application database records. Exit code 0 requires every check to pass; failed or skipped checks produce exit code 1. Offline harness smoke tests exercise control flow only and are not evidence of live model quality.
